Why AI gets your numbers wrong

Two teams. Two definitions of discount.

An AI tool can read your schema. It can't read the Slack thread where finance and growth agreed what discount means. So it picks one, and nobody notices.

  • Definitions

    The same word means two numbers

    Discount, active user, churn. Each team has its own formula, a few percent apart on every row.

  • Known scars

    Your data has history

    A week of missing refunds. A status change halfway through a quarter. Your analysts route around these from memory. A model can't.

  • Schema traps

    Joins fail quietly

    IDs stored as text in one table and numbers in another. UTC timestamps in an IST business. The totals still look plausible.

What we build

A context engine, in plain files you own.

We write down what your best analyst knows and connect it to the AI your team already uses. It lives in your git repository as Markdown and Python, so there's nothing to migrate later and nothing to lose if you stop working with us.

  • metrics/ decisions/

    Context notes

    One note per metric, decision and data trap, each with an owner and a date. Old definitions are marked superseded, never deleted.

  • CLAUDE.md

    Rules for the AI

    Ask when two definitions conflict. Never mix internal and investor numbers. Nothing ships without a person signing off.

  • lib/

    A tested query layer

    Joins, time zones and filters written once, so every answer starts from the same base tables.

  • checks

    Upkeep

    Checks catch stale notes, broken links and source tables that stopped updating, before a wrong number goes out.

Questions founders ask

Before you book

Do you need access to our data?

Read-only access to your warehouse during the sprint, with a per-person login you can revoke. We never need write access, and the context notes hold definitions, not customer data.

Which warehouses do you work with?

We've run this in production on BigQuery, Postgres, MySQL and Google Sheets. Snowflake and Databricks work the same way; we confirm the details in the audit.

Is this tied to Claude?

We set teams up on Claude because it handles large context well. The notes are plain Markdown, so any AI tool that can read files or connect over MCP can use them.

What happens when we stop working with you?

You keep everything. It lives in your repository and your area owners know how to update it. The retainer pays for new areas and upkeep, not for access.

We already have a semantic layer. Do we need this?

A semantic layer defines how a metric is computed. It doesn't record why it changed, which data to distrust or what to do when two teams disagree. We build on top of yours.

Can it help with fundraising?

Yes. We've built an investor data room with a context layer: exports, a dictionary for every file and documented data caveats, so an analyst on the other side can use AI on it without misreading it.
